# 기억 검색 낱말 설계 메모

범위: 조사가 붙은 한국어 질문이 기억과 같은 낱말을 말하는지 알아보는 규칙(K1), 그리고 질문 낱말을 모델로 넓히는 선택 기능(K2). 코드는 `domain/memory_terms.py`, `application/services/memory_recall.py`입니다.

## 아이디어 출처

- oh-my-openagent PR #9342, memory-core의 `bm25.ts`: 한글·한자·가나 글자 묶음을 두 글자씩 겹쳐 잘라 키워드 검색의 낱말로 쓰는 생각.
- 두 저장소의 라이선스는 비상업 제한이라 코드를 가져오지 않았습니다. 생각만 참고해 이 저장소에서 새로 썼습니다.

## K1: 낱말을 두 글자씩 겹쳐 자른다

- 한글·한자·가나 글자 묶음이 3글자 이상이면 글자 묶음 자체와 겹치는 2글자 조각(자료를 → 자료, 료를)을 낱말의 모양으로 가집니다. 2글자 묶음은 그대로 하나입니다. 다른 문자와 숫자는 2자부터 낱말입니다("AI", "5G").
- 질문 낱말은 그 묶음이나 조각 중 하나가 기억의 낱말에 있으면 맞은 것으로 칩니다. **맞은 수는 질문 낱말 하나에 한 번입니다.** 조각이 여러 개 맞아도 한 낱말입니다. 점수나 가중치는 만들지 않습니다.
- 기억의 낱말은 저장해 둔 `query_terms`가 아니라 회상할 때 기억의 본문에서 다시 나눕니다. 옛 규칙으로 저장된 기억도 새 규칙으로 찾아집니다. `query_terms` 필드는 호환을 위해 그대로 저장합니다.
- 적용하는 곳: `narrow_recall`(자동 기억은 질문 낱말 2개 이상, 사용자 정정은 1개), `order_recall`(맞은 낱말 수), `common_terms`(프로젝트 기억의 절반 이상에 있는 낱말), 저장할 때의 `content_reusable`(낱말 2개 이상).
- 이번에 더한 안전장치(요청 사항 밖): 어미 자체인 조각("하다", "에서" 등)과 영어 두 글자 조사·관사("of", "to" 등)는 낱말로 세지 않습니다. 그대로 두면 서로 상관없는 문장이 어미만으로 맞습니다. 아주 긴 글자 묶음은 앞 2,000자까지만 조각을 만듭니다.

## 알려진 한계

- 두 글자 조각은 흔한 어간("결과", "공개", "확인")도 맞게 합니다. 서로 다른 주제의 기억이 낱말 둘로 우연히 통과할 수 있습니다. 측정은 `docs/verification/memory-terms-20261003.md`에 있습니다.

## K2: 질문 넓히기 (조사당 모델 호출 한 번)

질문의 낱말과 기억의 낱말이 달라서(예: 질문은 "분석", 기억은 "대조") 기억을 못 찾는 경우를 위해, 조사마다 모델에게 검색어를 한 번 덧붙이게 합니다. 모델 답은 검색어일 뿐이며 어떤 기억을 부를지는 결정하지 않습니다. 점수나 가중치도 없습니다.

- 포트: `ports/memory.py`의 `MemoryQueryExpanderPort.expand(query) -> QueryExpansion`. `QueryExpansion`(`domain/memory_expansion.py`)은 동의어(`synonyms`), 주제를 다른 언어로 쓴 말(`keywords`), 관련어(`related`), 찾는 기억처럼 쓴 한 문장(`note_line`)이며 목록은 8개, 항목은 40자, 한 문장은 240자까지만 남깁니다. 모델 출력 상한은 300토큰입니다.
- 구현: `application/services/memory_query_expansion.py`의 `ModelMemoryQueryExpander`. 기억 관계 판정기와 같이 조사가 쓰는 `ModelPort` 하나만 부르고(새 모델 경로 없음), 역할은 `MEMORY_QUERY_EXPANDER`입니다. 호출에는 `purpose=MEMORY_QUERY_EXPANSION`이 붙어, 조사의 결과별 사용량(`result_usage`)에 합계의 일부로 "기억 검색어 넓히기"가 따로 보입니다.
- 호출 위치: `build_context`는 동기 함수라서 호출하는 쪽(`research_analysis.run`, `thread_analysis.analyze`)이 먼저 `widen_query`를 기다린 뒤 결과를 `expansion=`으로 넘깁니다. 한 조사 안에서 두 곳이 모두 부르므로 답은 `work.preprocessing_cache`에 두고 두 번째 호출자는 같은 답을 받습니다.
- 부르지 않는 경우: 기억 스위치가 꺼짐, 넓히기 스위치가 꺼짐, 후보 기억이 없음(저장된 기억 중 COMMIT이고 불러올 수 있는 것이 하나도 없음), 앞 조사를 잇는 질문(낱말 조건을 건너뛰므로 넓힐 이유가 없음). 이유는 선정 기록에 `NOT_ASKED`와 함께 남습니다.
- 실패: 호출 실패·20초 초과는 `EXPANSION_FAILED`, 형식이 틀린 답은 `EXPANSION_INVALID`로 기록하고 덧붙인 말 없이 평소대로 불러옵니다. 조사를 멈추는 신호(`ResearchFence`, 일시정지, 임대 상실)는 삼키지 않습니다.
- 선정 규칙: 질문 낱말만으로 들어온 기억이 먼저, 덧붙인 말이 있어야 들어온 기억은 그 뒤에 따로 묶입니다. 자동 기억의 "맞은 낱말 2개" 조건은 둘을 합쳐 세며, 덧붙인 말 중 질문에 이미 있는 낱말(같은 낱말이거나 그 낱말의 두 글자 조각)은 세지 않습니다. 선정 기록의 `matches`에 기억마다 `matched_by`(QUERY | EXPANSION), 맞은 낱말, 덧붙인 말이 남고 `expansion`에 호출 결과(상태, 사용한 덧붙인 말, 호출 번호)가 남습니다.
- 설정: 프로젝트별 "검색어 넓히기"(`ProjectMemorySettings.query_expansion`). 기본값은 `QUERY_EXPANSION_DEFAULT_ON` 상수 하나입니다. 실제 모델로 측정해 넓히지 않는 쪽이 낫다고 나오면 이 상수만 바꿉니다. `memory/settings/update`는 `query_expansion`을 생략하면 지금 값을 유지합니다.

## K3: 통째로 맞은 낱말 하나는 필요하다

두 글자 조각은 흔한 어간(결과, 공개, 확인)도 맞게 해서, 서로 다른 주제의 기억이 조각만으로 낱말 둘을 채워 들어오는 문제가 재현에서 확인되었습니다(docs/verification/memory-terms-20261003.md). 그래서 자동 기억은 질문 낱말 중 글자 묶음 그대로 맞은 것이 1개 이상 있어야 하고, 조각으로만 맞은 낱말은 약한 일치(match_strength=PARTIAL)로 선정 기록에 남깁니다. 덧붙인 말도 같은 원칙이며 사용자 정정의 기준(낱말 1개)은 그대로입니다.
